Public APIs

All APIs currently default to double precision (Float64). Single precision (Float32) is supported but still experimental, as it still needs testing to avoid type promotion.

TrixiCUDA.LobattoLegendreBasisGPU — Type
LobattoLegendreBasisGPU([RealT = Float64,] polydeg::Integer)

Create a nodal Lobatto-Legendre basis for polynomials of degree polydeg, partially storing and operating on GPU arrays (CuArray). This basis is designed for GPU-accelerated discontinuous Galerkin spectral element method (DGSEM).

Experimental implementation

This is an experimental feature and may change or be removed in future releases due to ongoing performance optimizations.

TrixiCUDA.DGSEMGPU — Function
DGSEMGPU(; RealT = Float64,
           polydeg::Integer,
           basis_type = LobattoLegendreBasisGPU,
           surface_flux = flux_central,
           surface_integral = SurfaceIntegralWeakForm(surface_flux),
           volume_integral = VolumeIntegralWeakForm())

Create a discontinuous Galerkin spectral element method (DGSEM) optimized for GPU computations, using a Lobatto-Legendre basis that is partially implemented on the GPU (LobattoLegendreBasisGPU). Currently, only the LobattoLegendreBasisGPU type is supported; other bases are not supported by the CUDA kernels.

Supported volume integrals are VolumeIntegralWeakForm, VolumeIntegralFluxDifferencing, and classic VolumeIntegralShockCapturingHG: identical default/blended high-order flux-differencing operators with first-order subcell FV. Generalized HG configurations with a different default operator or second-order FV are not yet supported.

Experimental implementation

This is an experimental implementation and may change or be removed in future releases due to ongoing performance optimizations.

                                uEltype=RealT,

Construct a semidiscretization of a hyperbolic PDE for GPU-accelerated computations. This version stores and manages computational caches on both GPU and CPU to achieve efficient data transfer. The boundary_conditions keyword must be specified explicitly.

TrixiCUDA.semidiscretizeGPU — Function
semidiscretizeGPU(semi::SemidiscretizationHyperbolicGPU, tspan;
                 jac_prototype=nothing, colorvec=nothing)

Wrap the GPU-accelerated semidiscretization semi as an ODE problem over the time interval tspan, which can be solved using the SciML ecosystem. The optional jac_prototype specifies the Jacobian matrix type and sparsity pattern, while colorvec provides column coloring to accelerate sparse Jacobian computation.

Experimental implementation

This is an experimental feature and may change or be removed in future releases due to ongoing performance optimizations.

Semidiscretization

TrixiCUDA.rhs_hyperbolic! — Function
rhs_hyperbolic!(du_ode, u_ode, semi::SemidiscretizationHyperbolicGPU, t)
rhs_hyperbolic!(du, u, t, mesh, equations, boundary_conditions,
                source_terms, dg, cache_gpu, cache_cpu)

Compute the hyperbolic right-hand side on the GPU.

The first method extracts the required data from semi and calls the second method.

The second method assembles the right-hand side from volume, interface, boundary, mortar, surface, Jacobian, and source operations. It writes du in place and returns nothing. The additional cache_cpu supports the current host-side HG indicator; 1D problems have no mortar stages.

calc_volume_integral!(du, u, mesh, equations,
                      volume_integral, dg, cache_gpu, cache_cpu)
calc_volume_integral!(du, u, mesh, nonconservative_terms, equations,
                      volume_integral, dg, cache_gpu, cache_cpu)

Compute the DG volume term on the GPU for weak form, flux differencing, or classic HG shock capturing. When omitted, the nonconservative trait is selected from equations. The additional cache_cpu argument is required by the current HG indicator implementation. Writes du in place; resetting du is fused into the first kernel.
